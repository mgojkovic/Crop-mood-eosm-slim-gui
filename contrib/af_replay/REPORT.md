## 1. Method

**Real data.** Logs parsed: AFCALIB.LOG x3, AFDIAG.LOG x1, AFDIAG29.LOG x1, AFDRIVE.LOG x6, AFPROBE.LOG x1, AFSEARCH.LOG x1, AFSPEED.LOG x1, MPUDRIVE.LOG x1, MPULAB.LOG x1. Move lines `ms phase cmd pos s g luma done_val flags done_ms ...` of AFDRIVE/AFCALIB are cut into *same-direction series*: a reversal move plus the same-direction moves after it (a reversal shifts every later point by one unknown offset, so positions inside a series are consistent, across series they are not). Series are broken at direction changes, unmeasured moves (`o`), phase-letter changes (`u`/`d` passes) and error/no-done moves.

**Curve fit.** Each series with >= 5 points is fitted with `B + A*exp(-(p-p*)^2/(2 sigma^2))`, separately for s and g (grid search over p* and sigma, B and A by linear least squares, B limited to 0.4..1.0 x the series minimum). A fit is accepted when R^2 >= 0.85, A/B >= 0.2, sigma in 5.5..290 and p* inside the series (+-10 pulses). Coarse series (step 80-100) are too sparse to fit s; g is fitted for steps <= 100.

**Simulator.** True lens position `x`, s peak at 0. `move(n)` adds `n` plus, when the direction differs from the previous move, a uniform random offset in [-R, +R] (R = 60 pulses by default). Same-direction moves are exact. FOCUS_DONE time: fast mode `178 + 0.72*|n|` ms (sd 95) or, with probability by size, the ~510 ms timer mode seen in the logs; after FOCUS_DONE 86 ms (unmeasured) / 165 ms (+ one sample) / 190 ms (+ stable pair), fitted from the log timestamps. Readings carry multiplicative Gaussian noise (sd 0.9 % per reading, 1/sqrt(2) for a pair). Curves are drawn from the accepted real fits (joint s and g) or synthetic ones (sigma_s 12-60, A/B 0.4-3). g additionally has a wide component (40 % weight, sigma 110) because the brief says g is broad (+-120) although the fitted g cores are narrow.

Continuous moves (`begin`/`next_sample`/`stop`): one LV frame every 42 ms, constant speed 0.40 pulses/ms after a 30 ms start delay, the frame shows the lens position one frame (42 ms) earlier, the algorithm converts time to position with its own velocity estimate (error sd 10 %) and the same lag. `stop()` lets the lens coast for the stop latency (default 60 ms).

**Algorithms** (all over the same camera API, same constants as `afd_run` where they overlap):

- **A** - baseline: probe + coarse g + pass A + retrace
- **B** - continuous sweep + stepped retrace
- **C** - continuous sweep + continuous retrace (stop on threshold)
- **D** - model jump (3 g samples, known sigma) + pass A + retrace
- **E** - warm start (+-40 check) -> pass A, else B
- **F** - baseline with predictive stop (log-parabola)

- A mirrors `afd_run`: probe step 100 on g (95 % rule, ambiguous band), coarse g climb (stop at < 80 % once or < 90 % twice or flat), pass A (20-pulse steps on s from one coarse step before the g peak, stop after 2 points < 70 % of max, widen by 200 once when the max is the first point, no-peak check at 115 %), retrace 1 (back 60 + steps-since-max x 20, stable pairs, stop at s >= 90 % of the pass A max), retrace 2 (80 %, back 140+), then walk to the best point. Run cap 15 s.
- B/C sweep: one 400-pulse move, one sample per frame, stop when the s peak (>= 1.15 x floor) has dropped below 70 % twice or when the start reading stays the best (peak behind), peak = log-parabola vertex of the 3 best frames, zig-zag with growing length if nothing is seen. B retraces stepwise (back 80 / 160), C continuously: back move to peak - 80, a continuous move with stop at s >= 85 % of the sweep peak, then the stepped retrace if the landing is below 90 %.
- D: 3 same-direction 40-pulse moves with one g sample each; Gaussian on g with the calibrated width (+-10 %) and the floor known to +-15 %; amplitude and p* fitted; no signal (A/B < 0.25) or no peak in pass A -> B.
- E: s at the start and after +20, +20; rising / peak at the middle point -> pass A + retrace without coarse search; falling -> the same the other way; flat -> B.
- F: A with predictive stop: coarse g climb stops at the first drop below 93 % of the best and uses the log-parabola vertex as the g peak; pass A stops after the first drop below 92 % when the log-parabola through the 3 points is concave and uses its vertex as the peak.

**Metrics.** Over N random trials per cell: success = final true s >= 90 % of the true peak s (noise-free, at the final true lens position); time = simulated ms from the start until the algorithm ends (capped at 15 s, counted as is); moves = FOCUS_DONE count; travel = sum of |pulses| commanded. Start defocus is uniform in |x0| and a random sign: near 15-120, mid 120-300, far 300-600, warm 0-50 pulses. All algorithms see the same curves, start positions and per-trial random seeds.

## 4. Recommendation

Headline (cold start = near + mid + far, defaults, real curves): **A** 72 % / 10.8 s (p90 15.0 s); **B** 85 % / 5.0 s (p90 11.8 s); **C** 88 % / 5.6 s (p90 11.9 s); **D** 78 % / 8.9 s (p90 15.0 s); **E** 84 % / 6.1 s (p90 13.9 s); **F** 76 % / 9.5 s (p90 15.0 s). Warm (|defocus| <= 50): A 85 % / 9.3 s; B 81 % / 3.2 s; C 91 % / 3.9 s; D 87 % / 8.5 s; E 70 % / 6.7 s; F 88 % / 7.7 s.

1. **The stepped baseline (A) is slow because it walks, not because it is inaccurate.** Its simulated time (median 10.8 s, 23 moves cold; 9.4 s near, 10.4 s mid) matches the field runs (8.5-10.6 s), and it hits the 15 s cap in 14 % of the cold trials (far start: the coarse climb is limited to 1500 pulses and needs the g slope). The two sweep algorithms are roughly twice as fast (B 5.0 s, C 5.6 s median, 7-9 moves) and at least as often in focus.
2. **Recommended direction: a continuous sweep to find the peak (B), finished by the existing stepped feedback retrace, with C (continuous retrace + stop on threshold) as an optional upgrade.** C buys +3 points of success for +0.6 s over B at the default 60 ms stop latency, but it is the more fragile one: its success falls from 93 % (stop latency 0) to 79 % (200 ms), and both lose when the real sweep speed is high (79 % / 75 % at 0.8 pulses/ms vs 86 % / 91 % at 0.4). The stepped retrace keeps the camera's proven landing rule, so B degrades more gracefully. Build B first, measure the stop latency and sweep speed with AFSWEEP.LOG, then decide on C.
3. **Reversal offset is the dominant risk for every algorithm.** Going from R = 0 to R = 60 costs A 7, B 5, C 1 and F 10 points; at R = 100 A falls to 60 %, B to 72 %, C to 79 % and at R = 150 to 38 / 57 / 64 %. With the retrace margin matched to R (B+/C+, oracle) B and C recover only part of it (78 % / 85 % at R = 100), (the remaining loss is not analysed here); a measured R (the repeated-reversal calibration the next field test should run) is worth more than any algorithm choice here.
4. **Cheap, low-risk improvement of the current code: F (predictive stop in the stepped climb).** It cuts 1.4 s (10.8 -> 9.5 s median, cold) and gains +4 points; the gain is largest when the reversal offset is small (R = 0: 96 % vs 87 %). It needs no new firmware command, so it can ship before the sweep work.
5. **Not recommended as designed:** D (model jump, 78 % / 8.9 s cold) pays for three probe moves and then still needs pass A + retrace; it also depends on knowing sigma_g and the floor. E (warm start, 70 % / 6.7 s warm) is beaten by simply running B or C even for small defocus (81 % / 3.2 s and 91 % / 3.9 s warm), because the +-40 check is ambiguous near the peak and then falls back to B.
6. **Next measurements that would change these conclusions:** AFSWEEP.LOG (sweep speed and the real FOCUS_DONE time, which fixes time->position and the peak width in continuous motion), a stop() test on a running (9,1) move (latency, coast distance), and a reversal test with many repeats at several move sizes (distribution and size dependence of the offset). Then rerun this tool: `python3 af_replay.py --logs <dir>`; AFSWEEP series are picked up automatically.

## 5. Assumptions and their uncertainty

1. **Reversal offset: uniform in [-R, +R], R = 60, redrawn at each reversal, same-direction moves exact.** Only loosely supported
   (calib backlash_est values were -120..+120 with both signs, `repeat_up` 80). Real offsets might depend on the move size or be correlated between consecutive reversals.
   The R table shows how strongly the results depend on it; the algorithms keep their constants (designed for ~60), so a larger R hurts the 20-pulse retrace the most.
2. **Sweep speed 0.40 pulses/ms is a guess.** The logs only give FOCUS_DONE, which for moves >= 60 pulses is mostly the 510 ms timer value. The speed table shows the effect; this is the first thing AFSWEEP.LOG will settle.
   Continuous motion is modelled as constant speed after a 30 ms start delay, no acceleration profile and no motion blur of s.
3. **Stop latency** is a parameter (30/60/120 ms), the coast distance is latency x speed. Whether `stop()` (FOCUS_STOP, (9,3,1)) halts a (9,1) move at all is untested.
4. **Curve shape.** A single Gaussian on a flat floor for s (fits R^2 mostly > 0.95 in the stepped windows); the real tails are not modelled and the pool has only 22 curves from a handful of scenes
   (same lens, x5, a few distances), so the scene variety (sigma 17-30 pulses) is probably too narrow; the synthetic family widens it to 12-60. g has an assumed wide component.
   The floor is a constant (no scene gradient), so false peaks and texture changes are not simulated.
5. **Noise** is multiplicative Gaussian, ~1 % per reading from static repeats, independent between readings. Real noise has outliers (flicker, LV recovery) and motion blur in continuous moves is ignored.
6. **Positions** are only known to the algorithms through commanded pulses; the lens range / end stops and Canon's own AF interplay are not modelled (travel is unbounded).
7. **Timing** of stepped moves comes from the logs (fast mode / timer mode mixture, fitted overheads); the timer-mode share depends on size only in the model.
8. Algorithms D/E/F are first designs, not tuned: thresholds (92/93 %, 2 %, 0.25) were set once, not optimised. The comparison says which *structure* is promising, not the best constants.
9. Success counts only the final true s >= 90 % of the true peak. The algorithms' own landing test is 90 % of an *observed* maximum (a noisy, frame-sampled one for B/C), so some failures are the landing criterion rather than a miss of the peak.
