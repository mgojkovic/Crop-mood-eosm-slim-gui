# AF lab report: candidate search algorithms

Generated by `contrib/af_replay/af_lab.py` (`--trials 200 --seed lab1`, 15 s).  Real fitted curve pool: 48 curves from `/private/tmp/claude-501/-Users-mgojkovic-repos-Crop-mood-eosm-slim-gui/ea95f17a-e40e-4903-a809-65ac8220d6dc/scratchpad`.

**This is a simulation, not camera data.**  The curve shapes, noise, move timing and the `Cam`/`Ctl` API are those of `af_replay.py` (fitted from the real logs); the lens model (reversal offset, sweep speed, stop latency) and the Auto-refocus reference bookkeeping are assumed.  Treat the numbers as a ranking of structures and the sensitivity tables as bounds, not as predicted camera numbers.  See the last section.

The **real-curve** tables are the primary result; the same algorithms are also run on the synthetic curve family as a secondary check (section 2b), so a structure that only wins on one curve family is visible as such.

## 1. Method

**Reused from `af_replay.py` (imported as a library, not modified).**  Fitted `B + A*exp(-(p-p*)^2/(2 sigma^2))` curve pool, per-move timing and overheads, multiplicative reading noise (sd 0.98 % per reading, pair = /sqrt(2)), relative pulse moves with a uniform reversal offset in +-R (R = 60), continuous moves with one LV frame per 42 ms, 0.40 pulses/ms after a 30 ms start delay, one frame image lag, a 10 % velocity-estimate error and a 60 ms `stop()` coast.  All candidates use the same `Cam`/`Ctl` API and the same `move`/`measure`/`begin`/`next_sample`/`stop` calls as the firmware.

**What the recovered real logs add to the model.**  The run parses the whole session pool (card3..card18) and uses it in three ways:

- **AFSWEEP.LOG** (sweep geometry): 2 file(s), 11 unique series, 7 fitted `s` curves (sigma median 108 pulses, range 37-147) against 34 stepped same-direction fits (sigma median 19).  `af_replay` puts the accepted AFSWEEP series into the curve pool automatically (`sweep_series`, positions from time with the measured done time).  The wider sweep sigmas are kept: they are what makes the far-class results in this report different from the 22-curve pool of the earlier REPORT.md.
- **AFSTOP.LOG** (stop test): k1 plan=150 ms -> t_stop=161 t_done=523; k2 plan=250 ms -> t_stop=255 t_done=544; k3 plan=350 ms -> t_stop=380 t_done=501; k4 plan=450 ms -> t_stop=469 t_done=506.  Every planned stop still ended with FOCUS_DONE at the ~500 ms timer value and the samples continue past the planned stop time.  A follow-up per-sample analysis ([EOSM-AF-STOP-ANALYSIS.md](../../doc/EOSM-AF-STOP-ANALYSIS.md), `contrib/af_test/stop_analysis.py`) shows the sharpness trace keeps changing for 300-500 ms after the stop command in 12/12 trials (median post-stop |slope| ~43 %/s), i.e. `(9,3,1)` does **not** halt the `(9,1)` move.  That is why the "stop does nothing" row is in the sensitivity tables and why C/G are treated as conditional.
- **AFRTEST.LOG** (Auto-refocus reference erosion): the two `RT_REF` sequences are 97338 -> 84320 -> 70812; 115624 -> 94755 -> 85927 -> 76595 `ref_s`; the per-re-landing ratios are 0.866, 0.840, 0.820, 0.907, 0.891 (median **0.866**).  The local-refocus experiment therefore uses that measured factor as the calibrated ratchet scenario, plus 0.85 as a worst case.

**New candidates (all on top of the same API).**

- **A** - baseline: probe + coarse g + pass A + retrace
- **B** - continuous sweep + stepped feedback retrace
- **C** - continuous sweep + continuous retrace (stop on threshold)
- **F** - baseline with predictive stop in the stepped climb
- **G** - sweep with predictive braking (log-parabola vertex + CUSUM)
- **H** - Gaussian fit of a coarse bracket + vertex jump + verification
- **I** - Brent/golden-section inside a coarse bracket
- **J** - two-sided linear slope probe -> direction/bracket
- **K** - DFD-style calibrated relative-blur jump + verification

- **local_v0** - current afd_run_local logic (reference from bookkeeping)
- **local_v1** - handover 4.1: wider +-4*fine probe, no in-focus exit on drop path
- **local_v2** - v1 + per-scene high-water-mark reference (handover 4.2)
- **keep** - no search: trust the previous landing
- **B** - full sweep + retrace on every trigger

More detail: **G** fits a parabola to `ln s` through the last 5 frame samples, predicts the vertex and calls `stop()` when the vertex is inside the modelled coast window `v_alg*(stop_lat + 0.5*frame)`; a 2-frame negative-slope / CUSUM rule is the fallback, and the proven stepped feedback retrace does the landing.  **H** climbs in 40-pulse steps, fits the Gaussian with the floor free, and only jumps when R^2 >= 0.90, A/B >= 0.2, sigma in 8..110 and the peak is prominent; one verification sample decides between the jump and a Brent fallback.  **I** uses the same coarse bracket and then golden-section (6 iterations, pair samples).  **J** measures s at -40/0/+40 and uses the sign of the slope for the direction; a peak inside the span goes straight to Brent, a one-sided slope to the coarse climb.  **K** measures s at 0 and +60, inverts the *calibrated* Gaussian shape (`p* = D/2 + sigma_cal^2 ln(r)/D`, sigma_cal has a +-10 % error, floor +-10 %) and jumps; one verification, then the mirrored side (the documented side ambiguity), then B.

**Metrics.**  Success = final true s >= 90 % of the true peak s (noise-free, at the final true lens position).  "soft" = final true s in 75..90 % (a near miss / a soft landing), "hard" = below 75 %.  Time = simulated ms until the algorithm ends (capped at 15 s); moves = FOCUS_DONE count; travel = sum of |pulses|.  All algorithms see the same curves, start positions and per-trial seeds.  With N = 200 per cell the 1-sigma Monte-Carlo error of a success rate is about 3.5 points.

## 4. Reference erosion and the local Refocus search

`afd_run_local` probes +-2*fine, climbs on the better side and otherwise takes an "in focus" exit.  In the field the Auto-refocus reference is re-set from the new settled sample after every landing (`aref_mpu_finish`/`aref_mpu_settle`), so it ratchets down toward the soft landings.  The recovered `AFRTEST.LOG` gives the real sequences:

|---|---|---|---|
| 20261019-144447 | 97338 -> 84320 -> 70812 | 0.866, 0.840 | 82X, 92ok, 83X, 96ok, 98ok no-run |
| 20261019-143547 | 115624 -> 94755 -> 85927 -> 76595 | 0.820, 0.907, 0.891 | 88X, 95ok, 77X no-run, 91ok, 87X no-run |

We model the reference as an external *scenario* parameter (from the bookkeeping, not from the search): **fixed** at the true scene peak, **ratchet_field** = the median measured factor **0.866** per landing, and **ratchet85** = 0.85 (a worst case).

A sequence is 5 triggers of a tracked scene that drifts by +-(0-50 warm / 50-150 mid) pulses between triggers; the lens stays where the previous run landed.  Curves are shared by all variants and scenarios.  Only attempts with a trigger reading < 98 % of the reference are counted.  The real Refocus test scored no-trigger trials too (def=150 and def=400 never ran yet were scored), because the reference had been re-based downward; that is a test-design bug, not a local-search behaviour, and it is excluded here.

Reading: variant 0 is the current code.  In the warm class with a **fixed** reference it already succeeds only 50 % and lands at 80-90 % of the reference in 10 % of the triggered attempts: the +-2*fine probes are blind at roughly half the probe span, so the "no side improves" exit is taken at a genuinely defocused position.  Under the measured ratchet its acceptance threshold falls with the reference (trajectory 1.00 -> 0.49), success is 45 % and the 80-90 % band is 7 %.  Variant 1 (wider probe, no in-focus exit on a drop trigger) reaches 49 % (soft 7 %, 80-90 % band 8 %); variant 2 (per-scene high-water-mark reference) keeps the effective reference at 1.00 instead of 0.49, reaches 47 % and cuts the 80-90 % band to 5 %, at the cost of more B fallbacks (67 % vs 62 %).  For the mid class the difference is smaller (47 % / 47 % / 48 %) because most triggers already fall back to B.  Even the fixed local search stays below the full-sweep B on the same triggers (72 % vs 50 %), and B is not slower here, so the local shortcut buys moves, not accuracy.  The reversal-offset table is the reason: at **R = 0** local_v0 reaches 82 % (B 83 %), at **R = 60** it falls to 45 % (B 72 %) and at **R = 100** to 25 %: a 40-pulse probe is inside the reversal uncertainty, so the direction decision is close to a coin flip.  The acceptance-rule fix is cheap and worth porting, but the local search only pays off once the reversal offset is measured or compensated.

**Headline.**  Cold (near+mid+far), real curves, N per cell: **G** 90 % / 4.1 s; **J** 87 % / 5.4 s; **C** 86 % / 4.3 s; **B** 85 % / 4.0 s; **H** 78 % / 6.1 s; **F** 77 % / 9.8 s; **I** 77 % / 6.2 s; **A** 74 % / 10.8 s; **K** 73 % / 5.7 s.

**Curve-family check.**  Top 3 on the real curves: G, J, C; top 3 on the synthetic family: C, G, B; in both: **G, C**.  A structure that is near the top on both curve families is the one to trust; a structure that only wins on one family (or on a threshold constant) should not drive the port.

1. **The simulated ranking is G > J > C > B > H > F > I > A > K; the two structures that depend on stop() are C and G.**  C 86 % / 4.3 s, G 90 % / 4.1 s, B 85 % / 4.0 s (the baseline).  C lands by stop-on-threshold and has no other landing; when the field fact that `(9,3,1)` does not halt a running `(9,1)` move is modelled, C falls to 65 % (B stays 79 %, G 84 %).  Predictive braking (G) is a stop decision too: with a dead stop it cannot brake and degrades to a full sweep, keeping B-like accuracy but losing the time it was meant to save.  The shippable conclusion today is to keep B (it is robust to a dead stop and needs no new command) and to invest in the landing/acceptance rule rather than in a new search; do not build a new search around stop() before the stop test exists.  F is only a small win over the stepped A and nowhere near B, so it is not the priority here.
2. **The single measurement that most changes the roadmap is whether any command halts a running move** (then C/G/predictive braking become available; the model puts the best stop-dependent structure up to ~5 points above B and shortens the p90 tail), followed by the reversal-offset distribution.  If the stop works, predictive braking (G) is the target with C as the alternative; if it does not, the sweep must run to its end and the win is only in the landing rule.
3. **Auto refocus: port the handover 4.1/4.2 fixes, but the reversal offset is the real blocker.**  On the measured ratchet the current logic has 45 % success and leaves 7 % in the 80-90 % band of the pre-trigger reference; the wider probe plus "no in-focus exit on a drop trigger" raises success to 49 % (band 8 %), and adding the per-scene high-water mark keeps the effective reference at 1.00 with 47 % success and a 5 % band.  Both are cheap and need no new command, so port local_v2 behind the existing trigger.  But the model says the local search only approaches B when R is small; measuring/compensating R is worth more than the probe change.  Also consider running B directly for the Refocus test: in this model it is both more accurate and not slower for small defocus.
4. **Model-fit + jump (H) and Brent (I) are not competitive as cold-start engines.**  H 78 % / 6.1 s, I 77 % / 6.2 s vs B 85 % / 4.0 s.  The reason is structural: a 40-pulse staircase cannot resolve a 10-20-pulse peak, and every absolute jump/probe adds a reversal whose offset the algorithm does not know (the R table: H/I fall from ~90 % at R = 0 to ~45 % at R = 150).  Keep the idea only as a warm-start "well-behaved curve, jump" branch, with a sweep fallback.
5. **Two-sided slope probe (J) is cheap and close to B** (87 % / 5.4 s cold).  It is a low-risk direction replacement for the fixed probe, but it does not change the overall structure.  **DFD (K)** (73 % / 5.7 s) cannot be recommended: besides the missing `sigma_s(p)` calibration it fails exactly where DFD is needed (low contrast, far defocus) and the floor/side ambiguity is real, as the implementation doc warned.
6. **Field tests that would confirm/refute this, in order:**  (i) a stop() test on a running `(9,1)` move at several delays (does it halt? how far does it coast?) - decides C/G; (ii) a reversal test with many repeats at several move sizes - the distribution of R decides the local search and every jump algorithm; (iii) AFSWEEP.LOG at several sweep speeds - fixes the time->position model B/G depend on; (iv) a Refocus test with local_v2 and logging of the scene high-water mark, the landing s and the trigger reading - confirms the ratchet and whether the HWM stops it.  The signal to watch in (iv): if the logged reference still falls after a landing, the aref_mpu_finish bookkeeping is the bug, not the search.

(Note: the baselines are re-run inside this harness, so their numbers differ from REPORT.md by Monte-Carlo noise and by the larger pool of recovered logs; the comparison between algorithms is apples-to-apples because they share curves, starts and seeds.)

## 6. Assumptions and their uncertainty

This tool re-uses the `af_replay.py` model and its documented uncertainties, and adds the following assumptions of its own:

1. **Reversal offset R** (uniform, redrawn at each reversal, default 60 pulses, same-direction moves exact).  Unmeasured; the R table is the bound.  All candidates were designed with R ~ 60 in mind, none was retuned after the fact.
2. **Sweep speed 0.40 pulses/ms** is still a parameter: the AFSWEEP logs give geometry and the fitted widths, but their `done` times are also the ~510 ms timer in several cases, so a true time->position calibration stays open.  G, H/I/J/K fallbacks and the step-count budgets all depend on it.
3. **Stop latency** (default 60 ms) is unmeasured.  G brakes using an assumed 60 ms coast; with a true 200 ms it overshoots.  The latency table is the bound and the first field test (stop a running (9,1) move at several delays) would fix it.
4. **Curve pool**: 48 real fitted curves, including the accepted AFSWEEP series; the synthetic family (section 2b) is the widened-scene secondary check.  A single Gaussian on a flat floor; the real tails, false peaks and texture changes are not modelled.  The pool is larger and broader than the 22-curve pool of the earlier REPORT.md because the recovered card3..card18 logs add fits.
5. **Reading noise** is multiplicative Gaussian, ~1 % per reading (0.98 % fitted from these logs), independent; real outliers, exposure steps and motion blur are not modelled except in the erosion scenario.
6. **Reference bookkeeping** in the local experiment is a scenario: fixed, the measured median ratchet **0.866** (per re-landing ratios from the two AFRTEST.LOG files), and a 0.85 worst case.  The measured ratios span 0.82-0.91 and are not a single constant; the scenario bracket reflects that.  The scene drift between triggers (0-50 / 50-150 pulses) and the 5-trigger sequence are assumptions; the end stop (the suspected cause of the real +60/+150 failures) is *not* modelled, so the local numbers probably understate the field failure rate.  The real test also scored no-trigger trials (a test-design bug caused by the reference re-basing); those are excluded here.
7. **DFD (K)** assumes a calibrated `sigma_s(p)` (+-10 %) and a floor estimate (+-10 %); the real calibration table does not exist yet.  It also uses s rather than a spectral relative-blur estimate, so K is an optimistic stand-in for DFD.
8. **stop()** is assumed to work in the main runs (coast = latency x speed).  The "stop does nothing" row models the contrary field observation; the per-sample follow-up ([EOSM-AF-STOP-ANALYSIS.md](../../doc/EOSM-AF-STOP-ANALYSIS.md)) now shows the stop did not halt the move in any of the 12 recovered trials, and it changes the value of C/G more than any threshold.
9. **Algorithm constants** of the new candidates were set once by reasoning, not optimised; the tables rank structures, not the best constants.  The Monte-Carlo error at N = 200 is ~3.5 points per cell; with two curve families (real primary, synthetic secondary) the ranking claims should be read as the intersection of the two.
